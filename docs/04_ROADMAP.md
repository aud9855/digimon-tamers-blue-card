# 04. 작업 목록 (Roadmap)

> 다음에 무엇을 할지, 언제 끝났다고 할 수 있는지를 적습니다.
> 규칙은 [02](02_RULES_SPEC.md), 코드 구조는 [03](03_ARCHITECTURE.md)이 기준입니다.

## 1. 일하는 방법

- **작업 하나 = 세션 하나 = 브랜치 하나.** 새 세션에서 "T0-4 진행해 줘"처럼 작업 번호로 시작합니다.
- 시작할 때: 이 문서에서 그 작업을 읽고, "먼저 읽을 것"에 적힌 02·03의 절을 읽습니다.
- 끝낼 때:
  1. `npm run typecheck`, `npm run lint`, `npm test`가 모두 통과
  2. 그 작업의 "끝났다는 기준"을 하나씩 확인
  3. 아래 표의 상태를 `완료`로 바꾸고 커밋·푸시
- 앞 번호 작업이 끝나야 다음 작업을 시작합니다 (같은 단계 안에서 순서대로).
- **멈추고 사용자에게 물어야 하는 때**:
  - 02 문서에 답이 없거나 두 문서가 서로 다를 때 (추측해서 채우지 않음)
  - 규칙을 바꿔야 풀리는 문제일 때
  - 03 문서의 표에 없는 라이브러리가 필요할 때
  - 그림·소리 파일을 밖에서 가져와야 할 때

### 모델 안내
- 이 문서들은 Opus medium으로 구현해도 되도록 썼습니다.
- 아래 작업은 판단이 많이 들어가므로 더 높은 설정(Opus high 또는 Fable)을 권합니다: **T0-11 밸런스 조정**, **각 단계 시작 전 규칙 확정**(T2-1, T3-1), **T1-4 연출**.
- 한 작업이 세션 하나에 안 끝나면, 끝난 데까지 커밋하고 이 문서의 그 작업 아래에 "남은 것"을 적어 둡니다.

### T0-4 전투 1: 턴, 카드, 효과, 피해
- **먼저 읽을 것**: 02의 3.1~3.6, 3.8, 3.9, 3.11, 4절
- **만들 것**: `battle/start.ts`, `turn.ts`, `cards.ts`, `effects.ts`, `damage.ts`, `tests/helpers`(원하는 덱·손패·적으로 전투를 만드는 함수), `damage.test.ts`, `turn.test.ts`, `cards.test.ts`

- **끝났다는 기준**:

### T0-5 전투 2: 적, 당겨쓰기, 진화

- **만들 것**: `battle/enemy.ts`, `evolve.ts`, 당겨쓰기와 가속, `tests/helpers/fixtures.ts`(시험용 완전체·궁극체 형태), `enemy.test.ts`, `overdraw.test.ts`, `evolve.test.ts`
- **끝났다는 기준**:
  - 진화 비용 표(02 3.7)의 6칸이 모두 테스트됨: 비용 계산 함수를 따로 두어 6칸을 확인하고, 시험용 형태로 성장기에서 궁극체까지 실제로 진화해 봄
  - 미히라몬이 HP 50% 이하에서 **다음 인텐트를 정할 때** 페이즈가 바뀌고, 포효를 한 번만 하고, 그다음 행동이 "공격 18"임
  - 가속: 턴 끝 부여, 공격에서만 소모, 방어 행동에서는 유지
  - 진화하면 임시 HP, 필살기 카드, `evolvedThisTurn`. 전투가 끝나면 모두 사라지고 HP만 남음
