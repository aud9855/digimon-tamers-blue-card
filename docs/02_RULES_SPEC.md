# 02. 규칙 명세 (Rules Spec)

> 이 문서가 **규칙의 기준**입니다. 구현은 여기 적힌 순서와 공식을 그대로 따릅니다.
> 수치(HP, 피해, 가격 등)는 초기값입니다. 구현 뒤에는 `src/data`가 수치의 기준이고, 밸런스 조정은 `src/data`만 고칩니다. 규칙(순서·공식)을 바꿀 때는 이 문서를 먼저 고칩니다.
> **[M0]** 표시가 없는 절도 모두 0단계 범위입니다. 나중 단계 규칙은 11절에만 있고, 그 전에는 구현하지 않습니다.

## 1. 용어

| 용어 | 코드 | 뜻 |
| :--- | :--- | :--- |
| 런 | `run` | 한 판 (테이머 선택부터 승리·패배까지) |
| 막 | `act` | 지도 하나 + 보스. 0단계는 1막만 |
| 단계 | `stage` | `rookie`(성장기) < `champion`(성숙기) < `ultimate`(완전체) < `mega`(궁극체) |
| 형태 | `form` | 파트너의 지금 모습 (길몬, 그라우몬…) |
| 메모리 | `memory` | 카드와 진화에 쓰는 자원. 턴마다 채워짐 |
| 실드 | `shield` | 피해를 먼저 막는 값 |
| 임시 HP | `tempHp` | 진화로 얻는 전투 한정 HP. 실드 다음, HP보다 먼저 깎임 |
| 힘 | `strength` | 공격 hit마다 더해지는 값 (전투 동안 유지) |
| 형태 공격력 | `power` | 지금 형태가 주는 공격 보너스. 힘과 따로 더함 |
| 약화 | `weak` | 걸린 쪽이 주는 공격 피해 ×0.75 |
| 취약 | `vulnerable` | 걸린 쪽이 받는 공격 피해 ×1.5 |
| 가속 | `accel` | 적 전용. 다음 공격 피해 1점당 +35% (`ACCEL_PER_POINT`) |
| 비트 | `bits` | 돈 |
| 디아크 칩 | `chip` | 유물 |
| 인텐트 | `intent` | 적이 다음에 할 행동 |

## 2. 런의 흐름

런은 항상 아래 **국면(phase)** 중 하나에 있습니다.

| 국면 | 들어오는 때 | 할 수 있는 행동 | 다음 국면 |
| :--- | :--- | :--- | :--- |
| `title` | 처음 | `startRun` | `reward` (테이머 특성으로 카드 고르기가 있으면) 또는 `map` |
| `map` | 칸 처리가 끝났을 때 | `chooseNode` | 칸 종류에 따라 |
| `battle` | 전투·강적·보스 칸 | `playCard`, `evolve`, `endTurn` | `reward` / `runWon` / `runLost` |
| `reward` | 전투 승리, 카드 고르기가 생겼을 때 | `pickCard`, `skipCards` | 남은 카드 고르기가 있으면 `reward`, 없으면 `map` (보스 뒤면 `actClear`) |
| `shop` | 상점 칸 | `shopBuyCard`, `shopBuyChip`, `shopRemoveCard`, `proceed` | `map` |
| `rest` | 휴식 칸 | `restHeal`, `restUpgrade` | `map` |
| `event` | 이벤트 칸 | `eventChoose` | `map` 또는 `reward` |
| `treasure` | 보물 칸 | `proceed` | `map` |
| `actClear` | 마지막 막이 아닌 막의 보스 보상이 끝났을 때 | `proceed` | 다음 막의 `map` |
| `runWon` | 마지막 막 보스를 이겼을 때 | 없음 | — |
| `runLost` | HP가 0 이하가 됐을 때 | 없음 | — |

- 0단계에는 1막만 있습니다. 1막 보스를 이기면 보상 없이 바로 `runWon`입니다.
- `actClear`와 막 넘어가기(7.6)는 0단계에서 **구현하고, 테스트 전용 데이터로 확인합니다** (03 8.1). 실제 게임에서는 2단계부터 쓰입니다.
- "마지막 막"은 `src/data/constants.ts`의 `ACT_COUNT`로 정합니다 (0단계: 1).

## 3. 전투

### 3.1 전투가 가진 상태
- 플레이어: `hp`(런의 `hp`를 그대로 씁니다. 전투용 복사본을 두지 않습니다), `shield`, `tempHp`, `stage`, 상태 효과(`strength`, `weak`, `vulnerable`), `memory`
- 카드 더미: 뽑을 더미 `drawPile`, 손패 `hand`, 버림 더미 `discardPile`, 소멸 더미 `exhaustPile`
- 이번 턴 표시: `evolvedThisTurn`, `freeEvolve`
- 적 목록 (각각 `hp`, `shield`, 상태 효과, `accel`, 인텐트, 페이즈·순환 위치)
- 전투 종류: `normal` / `elite` / `boss`

### 3.2 전투 시작 (이 순서대로)
1. `stage = rookie`, `shield = 0`, `tempHp = 0`, 플레이어 상태 효과 모두 0, `turn = 0`.
2. 런의 덱을 복사해 `battle` 난수로 섞어(피셔–예이츠) `drawPile`로 둡니다. `innate` 키워드 카드는 섞은 뒤 맨 위로 옮깁니다.
3. 조우 정의대로 적을 만듭니다. 각 적은 페이즈 0, 순환 위치 0이고 인텐트는 그 순환의 첫 행동입니다.
4. 가진 칩의 `onBattleStart` 효과를 얻은 순서대로 실행합니다.
5. 플레이어 턴을 시작합니다 (3.3).

### 3.3 플레이어 턴 시작 (이 순서대로)
1. `turn += 1`.
2. `turn >= 2`이면 `shield = 0`. (첫 턴에는 지우지 않습니다. 전투 시작 칩이 준 실드를 살리기 위해서입니다.)
3. `memory = maxMemory`.
4. `evolvedThisTurn = false`, `freeEvolve = false`.
5. 카드를 `HAND_SIZE`(5)장 뽑습니다 (3.4의 뽑기 규칙).
6. `turn == 1`이면 칩의 `onFirstTurn` 효과를 실행합니다.
7. 칩의 `onTurnStart` 효과를 실행합니다.

### 3.4 뽑기
- 한 장씩 뽑습니다. `drawPile`이 비었으면 `discardPile`을 `battle` 난수로 섞어 `drawPile`로 만들고 계속합니다. 둘 다 비었으면 멈춥니다.
- 손패가 `HAND_LIMIT`(10)장이면 뽑은 카드는 바로 `discardPile`로 갑니다.

### 3.5 카드 내기 (`playCard`)
**낼 수 있는 조건** (하나라도 어기면 잘못된 행동):
- 국면이 `battle`이고 카드가 손패에 있음
- `unplayable` 키워드가 없음
- 대상이 필요한 카드(효과 중에 `target: 'enemy'`가 하나라도 있음, 조건 효과 안쪽 포함)면 살아 있는 적을 `targetIndex`로 지정함. 대상이 필요 없는 카드에는 `targetIndex`를 주지 않음
- `memory - cost >= -MAX_OVERDRAW` (3.6)

**처리 순서**:
1. `memory -= cost`.
2. 카드를 손패에서 뺍니다.
3. 카드의 효과를 적힌 순서대로 실행합니다 (4.3).
4. 카드를 옮깁니다: `exhaust` 키워드가 있으면 `exhaustPile`, 아니면 `discardPile`.
5. 칩의 `onCardPlayed` 효과를 실행합니다.

**효과 실행 중 규칙**:
- 효과 하나(여러 번 때리는 피해는 hit 하나)를 처리할 때마다 **패배를 먼저 확인하고**(플레이어 HP 0 이하, 3.11), 그다음 적의 죽음을 확인합니다.
- 적의 HP가 0 이하가 되면 그 자리에서 죽습니다. 죽은 적을 대상으로 하는 남은 효과와 남은 hit은 건너뜁니다.
- 살아 있는 적이 없어지면 남은 효과를 모두 건너뛰고, 4·5번을 처리한 뒤 전투 승리(3.11)입니다.
- `randomEnemy`는 hit마다 살아 있는 적 중에서 `battle` 난수로 고릅니다.
- `allEnemies`는 살아 있는 적을 앞에서부터 차례로 처리합니다.

### 3.6 메모리와 당겨쓰기
- `memory`는 정수이고 **-3(`-MAX_OVERDRAW`)까지 내려갈 수 있습니다.**
- 플레이어가 턴을 끝낼 때 `memory < 0`이면 `N = -memory`이고, 살아 있는 모든 적이 `accel += N`을 얻습니다. 턴 도중에 음수였어도 `gainMemory`로 0 이상이 되어 있으면 가속은 없습니다.
- 가속의 효과는 3.8과 3.10에 있습니다.

### 3.7 진화 (`evolve`)
**조건**: 국면이 `battle`, `stage < run.maxStage`, 비용을 낼 수 있음(`memory - cost >= -MAX_OVERDRAW`). 한 턴에 여러 번 할 수 있습니다. 항상 한 단계씩 올라갑니다.

**비용**:
```
next = stage의 다음 단계
cost = EVOLVE_BASE_COST[next] - (index(run.maxStage) - index(next))
cost = cost + (칩의 evolveCostDelta 합)
cost = max(0, cost)
freeEvolve가 true면 cost = 0
```
`EVOLVE_BASE_COST = { champion: 3, ultimate: 3, mega: 4 }`, `index`: rookie 0, champion 1, ultimate 2, mega 3.

| 열린 최고 단계 | 성숙기로 | 완전체로 | 궁극체로 |
| :--- | :---: | :---: | :---: |
| 성숙기 (1막) | 3 | — | — |
| 완전체 (2막) | 2 | 3 | — |
| 궁극체 (3막) | 1 | 2 | 4 |

**처리 순서**:
1. `memory -= cost`. `freeEvolve`가 true였으면 false로.
2. `stage = next`. 형태가 그 단계의 형태로 바뀝니다.
3. `tempHp += 새 형태의 tempHp`.
4. 새 형태의 필살기 카드를 **임시 카드**로 만들어 손패에 넣습니다 (손패가 10장이면 `discardPile`로). 임시 카드는 전투가 끝나면 사라집니다.
5. `evolvedThisTurn = true`, 이번 전투의 진화 횟수 +1.
6. 칩의 `onEvolve` 효과를 실행합니다.

**형태 공격력**: 플레이어의 공격 hit마다 **지금 형태의 `power`**를 더합니다. 형태가 바뀌면 값이 바뀌는 것이고, 쌓이지 않습니다.

**전투가 끝나면** `stage`, `tempHp`, `shield`, 상태 효과, 임시 카드는 모두 사라집니다. `hp`만 런으로 돌아갑니다.

### 3.8 피해 계산
공격 hit 하나의 피해는 아래와 같습니다. 곱셈을 모두 한 뒤 **마지막에 한 번만 내림**합니다.

```
플레이어 → 적:
  raw  = amount + 형태 power + 플레이어 strength
  mult = attr(형태 속성, 적 속성) × (플레이어 weak > 0 ? 0.75 : 1) × (적 vulnerable > 0 ? 1.5 : 1)

적 → 플레이어:
  raw  = amount + 적 strength
  mult = (1 + 0.35 × 적 accel) × attr(적 속성, 형태 속성) × (적 weak > 0 ? 0.75 : 1) × (플레이어 vulnerable > 0 ? 1.5 : 1)

damage = max(0, floor(raw × mult))
```

**속성 배율** `attr(공격, 방어)`: 백신 > 바이러스 > 데이터 > 백신.
- 공격 쪽이 이기는 관계면 1.5, 지는 관계면 0.75, 같거나 한쪽이 `none`이면 1.

| 공격 \ 방어 | 백신 | 데이터 | 바이러스 |
| :--- | :---: | :---: | :---: |
| 백신 | 1 | 0.75 | 1.5 |
| 데이터 | 1.5 | 1 | 0.75 |
| 바이러스 | 0.75 | 1.5 | 1 |

**피해 적용 순서**: 실드 → 임시 HP → HP. (적은 임시 HP가 없으므로 실드 → HP.)
`loseHp` 효과는 계산 없이 HP에서 바로 뺍니다 (실드·임시 HP 무시).

**검산 예시** (테스트로 그대로 씁니다):
| 상황 | 계산 | 결과 |
| :--- | :--- | :---: |
| 길몬(바이러스, power 0)이 타격 6으로 알로몬(데이터) 공격 | floor(6 × 1.5) | 9 |
| 길몬이 타격 6으로 하피몬(백신) 공격 | floor(6 × 0.75) | 4 |
| 그라우몬(power 1), 힘 2, 연속 공격 4의 hit 하나로 하피몬(백신) 공격 | floor((4+1+2) × 0.75) | 5 |
| 길몬이 약화 상태로 강타 14, 취약 걸린 고부리몬(바이러스) 공격 | floor(14 × 0.75 × 1.5) | 15 |
| 고릴라몬(데이터) 공격 15, 가속 2, 길몬(바이러스)이 맞음 | floor(15 × 1.7 × 0.75) | 19 |
| 고부리몬(바이러스) 공격 6, 힘 2, 취약 걸린 길몬이 맞음 | floor((6+2) × 1.5) | 12 |

### 3.9 상태 효과
| 상태 | 값의 뜻 | 줄어드는 때 |
| :--- | :--- | :--- |
| `strength` | 더해지는 피해량 | 줄지 않음 (전투 끝까지) |
| `weak` | 남은 턴 수 | 걸린 쪽의 턴이 끝날 때 1 감소 |
| `vulnerable` | 남은 턴 수 | 걸린 쪽의 턴이 끝날 때 1 감소 |
| `accel` | 쌓인 점수 (적 전용) | 그 적이 공격이 들어 있는 행동을 한 뒤 0 |

- 같은 상태를 또 받으면 값을 더합니다.
- 플레이어가 적에게 건 취약 1은 그 적의 턴이 끝날 때 사라지므로, 건 턴에만 효과가 있습니다.

### 3.10 턴 끝과 적 턴 (`endTurn`, 이 순서대로)
1. `memory < 0`이면 살아 있는 모든 적에게 `accel += -memory` (3.6).
2. 손패에서 `retain` 키워드가 없는 카드를 모두 `discardPile`로 옮깁니다.
3. 플레이어의 `weak`, `vulnerable`을 1씩 줄입니다 (0 미만으로는 안 감).
4. 살아 있는 적을 앞에서부터 한 마리씩 처리합니다:
   1. 그 적의 `shield = 0`.
   2. 인텐트 행동의 효과를 순서대로 실행합니다. 플레이어 HP가 0 이하가 되면 즉시 패배(3.11)입니다.
   3. 그 행동에 `attack` 효과가 있었으면 `accel = 0`.
   4. 그 적의 `weak`, `vulnerable`을 1씩 줄입니다.
   5. 다음 인텐트를 정합니다 (3.10.1).
5. 플레이어 턴을 시작합니다 (3.3).

#### 3.10.1 적의 행동 고르기
- 적은 **페이즈** 목록을 가지고, 페이즈마다 행동 id의 **순환 목록** `cycle`이 있습니다.
- 다음 인텐트를 정할 때:
  1. **페이즈 전환**: 지금 페이즈에 `untilHpPct`가 있고 `hp / maxHp <= untilHpPct`이며 다음 페이즈가 있으면 다음 페이즈로 넘어갑니다.
     - 새 페이즈에 `onEnter` 행동이 있으면: 다음 인텐트는 `onEnter` 행동이고 순환 위치는 **-1**("순환을 아직 시작하지 않음")입니다.
     - 없으면: 순환 위치는 0이고 다음 인텐트는 순환의 첫 행동입니다.
  2. **전환이 없으면**: 순환 위치를 1 올리고(끝을 넘으면 0으로) 그 위치의 행동이 다음 인텐트입니다. 순환 위치가 -1이었다면 0이 되므로, `onEnter` 다음에는 순환의 첫 행동이 옵니다.
- 페이즈 전환은 이때만 확인합니다. 플레이어 턴 도중에 HP가 기준 이하로 내려가도, 그 적은 이미 보여 준 인텐트를 먼저 실행합니다.
- 0단계의 적은 모두 순환만 씁니다 (무작위 선택 없음).

#### 3.10.2 적 행동의 효과 (이 목록이 전부입니다)
| `op` | 값 | 하는 일 |
| :--- | :--- | :--- |
| `attack` | `amount`, `hits`(기본 1) | 플레이어에게 3.8대로 피해. hit마다 따로 계산·적용 |
| `shield` | `amount` | 그 적의 실드 + |
| `applyStatus` | `status`, `amount`, `target`: `self`·`player` | 상태 효과 부여 |
| `addCard` | `cardId`, `to`: `discard`·`draw`, `count` | **임시 카드**를 만들어 플레이어 더미에 넣음. 전투가 끝나면 사라지고 런의 덱에는 들어가지 않음 |

### 3.11 승패
- **패배**: 플레이어 `hp <= 0`이 되는 순간 (`loseHp`로도). 남은 처리를 모두 멈추고 국면은 `runLost`.
- **승리**: 살아 있는 적이 없어지는 순간. 3.5의 4·5번까지 처리한 뒤 전투 상태를 지우고 보상(7.1)으로 갑니다.
- 확인 순서는 항상 패배가 먼저입니다. 적이 모두 죽으면 남은 효과를 건너뛰므로(3.5), 예를 들어 디지털 해저드로 마지막 적을 잡으면 뒤의 "HP 4 잃음"은 실행되지 않습니다.

## 4. 카드

### 4.1 카드 정의
카드 하나는 `기본`과 `강화` 두 면을 가집니다. 각 면에 비용, 효과 목록, 키워드가 있습니다.

| 종류 `type` | 설명 |
| :--- | :--- |
| `attack` | 피해를 주는 카드 |
| `skill` | 그 밖의 카드 |
| `signature` | 필살기. 진화할 때만 생기고 보상·상점에 안 나옴 |
| `curse` | 저주. 보상·상점에 안 나옴 |

| 희귀도 `rarity` | 설명 |
| :--- | :--- |
| `basic` | 시작 덱 카드. 보상·상점에 안 나옴 |
| `common` / `uncommon` / `rare` | 보상·상점에 나옴 |
| `special` | 필살기·저주. 보상·상점에 안 나옴 |

| 키워드 | 뜻 |
| :--- | :--- |
| `exhaust` (소멸) | 내면 이번 전투에서 사라짐 |
| `retain` (보존) | 턴이 끝나도 손패에 남음 |
| `innate` (선천) | 전투 시작에 뽑을 더미 맨 위에 놓임 |
| `unplayable` | 낼 수 없음 |

- 카드 풀 `pool`: 테이머 id(그 테이머만), `neutral`(모두), `none`(보상·상점에 안 나옴).
  - 0단계에서는 `basic`·`common`·`uncommon`·`rare` 카드가 모두 `takato` 풀이고, 필살기와 저주는 `none`입니다.
  - 보상·상점에 나오는 카드: `pool`이 그 테이머이거나 `neutral`이고, 희귀도가 `common`·`uncommon`·`rare`인 카드.
- 강화할 수 있는 카드: `basic`, `common`, `uncommon`, `rare`이고 아직 강화되지 않은 카드. 강화는 한 번뿐입니다.

### 4.2 필살기 카드
- 모든 필살기는 `retain` 키워드를 가집니다.
- 내면 `discardPile`로 가서 그 전투 동안 덱을 돕니다. 전투가 끝나면 사라집니다.
- 0단계에서는 강화가 없습니다 (강화 면 = 기본 면).

### 4.3 효과 종류 (이 목록이 전부입니다)
| `op` | 값 | 하는 일 |
| :--- | :--- | :--- |
| `damage` | `amount`, `hits`(기본 1), `target`: `enemy`·`allEnemies`·`randomEnemy` | 3.8대로 피해. hit마다 따로 계산·적용 |
| `shield` | `amount` | 플레이어 실드 + |
| `draw` | `count` | 카드 뽑기 (3.4) |
| `gainMemory` | `amount` | 메모리 + |
| `heal` | `amount` | HP 회복 (최대 HP까지) |
| `loseHp` | `amount` | 플레이어 HP 직접 감소 |
| `applyStatus` | `status`, `amount`, `target`: `enemy`·`allEnemies`·`self` | 상태 효과 부여 |
| `freeEvolve` | — | `freeEvolve = true` (이번 턴 다음 진화 비용 0) |
| `addCard` | `cardId`, `to`: `hand`·`discard`·`draw`, `count` | 임시 카드를 만들어 넣음. `draw`는 무작위 위치. `hand`는 손패가 10장이면 `discardPile`로 (3.4, 3.7과 같음) |
| `ifStage` | `min`, `then`, `else`(선택) | 지금 단계가 `min` 이상이면 `then`, 아니면 `else` 실행 |
| `ifEvolvedThisTurn` | `then`, `else`(선택) | 이번 턴에 진화했으면 `then`, 아니면 `else` 실행 |

- 새 효과가 필요하면 이 표에 먼저 추가한 뒤 구현합니다.
- 2단계에서 `ifPlayedThisTurn`을 더합니다 (12.11).
- 카드 설명 글은 손으로 쓰지 않고 효과 목록에서 자동으로 만듭니다 (03 문서의 `describe`).

## 5. 디아크 칩

칩은 **발동 시점 + 효과 목록**이거나 **수치 보정**입니다. 효과는 4.3과 같은 목록을 씁니다.

| 발동 시점 | 때 |
| :--- | :--- |
| `onBattleStart` | 3.2의 4번 |
| `onFirstTurn` | 3.3의 6번 |
| `onTurnStart` | 3.3의 7번 |
| `onEvolve` | 3.7의 6번 |
| `onCardPlayed` | 3.5의 5번 |

| 수치 보정 | 뜻 |
| :--- | :--- |
| `evolveCostDelta` | 진화 비용에 더함 (음수면 할인) |
| `battleBitsBonus` | 전투 보상 비트에 더함 |
| `handSizeBonus` | 턴 시작에 뽑는 장수에 더함 |
| `maxHpBonus` | 얻을 때 최대 HP와 지금 HP를 함께 올림 |

- 칩 효과에서 `target: 'enemy'`는 쓸 수 없습니다 (`allEnemies`, `randomEnemy`, `self`만).
- 같은 칩은 한 번만 가질 수 있습니다.
- 테이머 특성도 칩과 같은 구조로 만듭니다 (8절).
- 2단계에서 수치 보정 `firstCardCostDelta`, 숨은 칩(`hidden`), 시작 칩(`start`)을 더합니다 (12.3, 12.7, 12.11).

## 6. 지도 생성

막 하나의 지도는 `map` 난수로 이렇게 만듭니다.

1. **칸 놓기**: 1~7행, 0~2열. 행마다 칸 수를 2 또는 3으로 정합니다 (반반). 2칸이면 뺄 열을 0·1·2 중에서 고릅니다.
2. **길 잇기**: `r`행 `c`열 칸은 `r+1`행에서 열 차이가 1 이하인 **모든** 칸과 이어집니다. 7행의 모든 칸은 보스와 이어집니다. (이 규칙이면 모든 칸에 들어오는 길과 나가는 길이 항상 하나 이상 있습니다.)
3. **칸 종류**: 행마다 아래 가중치로 칸마다 따로 정합니다.

| 행 | 칸 종류 (가중치) | 조우 난이도 |
| :---: | :--- | :--- |
| 1 | 전투 100 | 쉬움 |
| 2 | 전투 60, 이벤트 40 | 쉬움 |
| 3 | 전투 45, 강적 30, 이벤트 25 | 보통 |
| 4 | 첫 칸은 보물, 둘째 칸은 상점, 셋째 칸이 있으면 보물 50 · 상점 50 | — |
| 5 | 전투 45, 이벤트 30, 강적 25 | 보통 |
| 6 | 전투 50, 이벤트 30, 상점 20 | 보통 |
| 7 | 휴식 100 | — |

4. **보스 칸**: 8행 1열에 보스 칸 하나를 둡니다. 그 막의 보스 조우 목록에서 하나를 골라 적어 둡니다.
5. **내용 정하기**: 전투·강적·이벤트 칸은 지도를 만들 때 어떤 조우·이벤트인지까지 정해 칸에 적어 둡니다. 그 막의 난이도별 조우 목록, 강적 목록, 이벤트 목록에서 각각 **주머니 뽑기**로 고릅니다: 목록을 섞어 하나씩 꺼내고, 다 쓰면 다시 섞습니다.
6. **난수를 쓰는 순서** (같은 시드면 같은 지도가 나오게): 1번을 1행부터 7행까지 → 3번을 행 순서, 같은 행에서는 열 순서로 → 4번 → 5번을 행 순서, 열 순서로.
7. **이동**: 처음에는 1행의 아무 칸이나 고릅니다. 그 뒤로는 지금 칸과 이어진 다음 행 칸만 고를 수 있습니다. 7행 다음은 보스입니다.

## 7. 칸 처리

### 7.1 전투 보상
| 전투 종류 | 비트 (`reward` 난수, 양끝 포함) | 카드 고르기 | 그 밖 |
| :--- | :--- | :--- | :--- |
| 일반 | 12~18 | 3장 (가중치: 일반 60 · 고급 33 · 희귀 7) | — |
| 강적 | 28~35 | 3장 (일반 45 · 고급 45 · 희귀 10) | 가지지 않은 칩 중 무작위 1개 |
| 보스 (마지막 막 아님) | 60 | 3장 (희귀만) | 7.6 |
| 보스 (마지막 막) | — | — | 바로 `runWon` |

- 비트에는 칩의 `battleBitsBonus`를 더합니다.
- **카드 고르기 만들기** (한 장씩 반복):
  1. 가중치로 희귀도를 정합니다.
  2. 그 희귀도에서 나올 수 있는 카드(4.1) 중 **이번 고르기에 아직 안 뽑힌 카드**들에서 무작위로 하나를 고릅니다.
  3. 그런 카드가 없으면 한 단계 낮은 희귀도에서 2번을 합니다. 일반에도 없으면 고급, 희귀 순으로 올라가며 찾습니다. 어디에도 없으면 그 자리는 비웁니다 (고르기가 3장보다 적어짐).
- 비트와 칩은 `reward` 국면에 들어올 때 바로 받습니다. 카드는 `pickCard`로 1장을 받거나 `skipCards`로 건너뜁니다.
- **칩을 받을 차례인데 가지지 않은 칩이 없으면** 칩 대신 비트 50을 받습니다. 강적 보상, 보물 칸, 이벤트의 `addRandomChip` 모두 같습니다.

### 7.2 상점
- 들어올 때 `reward` 난수로 진열을 정합니다: 카드 5장(가중치 일반 55 · 고급 35 · 희귀 10, 7.1의 "카드 고르기 만들기"와 같은 방법), 가지지 않은 칩 2개 (남은 칩이 2개보다 적으면 있는 만큼만).
- 가격: 카드 일반 45 · 고급 70 · 희귀 130, 칩 140.
- 카드 지우기: 덱의 카드 1장을 없앱니다. 가격은 `60 + 20 × (이번 런에서 지운 횟수)`. 상점 한 곳에서 한 번만.
- 비트가 모자라면 살 수 없습니다. 산 물건은 진열에서 사라집니다. `proceed`로 나갑니다.

### 7.3 휴식
- `restHeal`: `floor(maxHp × 0.3)` 회복 (최대 HP까지).
- `restUpgrade`: 강화할 수 있는 카드 1장을 강화. 그런 카드가 없으면 고를 수 없습니다.
- 둘 중 하나를 하면 `map`으로 갑니다.

### 7.4 보물
- 들어올 때 가지지 않은 칩 중 무작위 1개를 받습니다 (`reward` 난수). `proceed`로 나갑니다.

### 7.5 이벤트
- 이벤트는 제목, 글, 선택지 목록입니다. 선택지마다 **런 효과** 목록이 있습니다.

| 런 효과 `op` | 하는 일 |
| :--- | :--- |
| `heal` / `loseHp` | HP 변화. `loseHp`로 0 이하가 되면 패배 |
| `gainBits` | 비트 + |
| `addRandomCard` (`rarity`) | 그 희귀도의 무작위 카드 1장을 덱에 (`event` 난수) |
| `offerCards` (`count`, `upgraded`, `rarity`) | 카드 `count`장 고르기를 만들고 `reward` 국면으로. `rarity`를 주면 그 희귀도만, 없으면 일반 전투 가중치. `upgraded`가 true면 강화된 상태로 |
| `addRandomChip` | 가지지 않은 칩 1개 |
| `addCard` (`cardId`) | 정해진 카드 1장을 덱에 (저주 포함) |

### 7.6 막 보스 뒤 (2단계부터 쓰임)
카드 고르기가 끝나면 `actClear` 국면이 되고, 이때 한꺼번에 적용합니다:
- `floor(maxHp × 0.5)` 회복
- `maxStage`를 한 단계 올림
- `maxMemory += 1`
- `proceed`를 하면 다음 막 지도를 만들고 `map`으로 갑니다.

## 10. 밸런스 목표 (0단계)

측정 조건: 오유민, 1막만, 시드 1~1000, 봇 정책별 1,000판 (봇의 동작은 03 문서 7절).

| 지표 | 목표 |
| :--- | :--- |
| `greedy` 봇 승률 | 55~70% |
| `random` 봇 승률 | 10% 이하 |
| 일반 전투 평균 턴 수 (`greedy`) | 3.0~5.0 |
| 강적 전투 평균 턴 수 | 4.5~7.0 |
| 보스 전투 평균 턴 수 | 6.0~10.0 |
| 일반 전투 한 번에 잃는 HP 평균 | 5~12 |
| 진화한 전투의 비율 (`greedy`) | 80% 이상 |
| 메모리를 당겨쓴 턴의 비율 (`greedy`) | 3~40% |
| 진화의 보람: `greedy` 승률 - `greedy`(진화 안 함) 승률 | +10~30%p |
| 진화 시점의 선택: `greedy` 승률 - `greedy`(2턴부터 진화) 승률 | -10~+10%p |

**지표 세는 법**:
- 승률 = `runWon`으로 끝난 판 ÷ 전체 판.
- 평균 턴 수 = 이긴 전투의 `turn` 평균 (전투 종류별).
- 잃는 HP 평균 = 이긴 일반 전투의 (시작 HP - 끝 HP) 평균. 회복 카드로 HP가 늘었으면 음수도 그대로 셉니다.
- 진화한 전투의 비율 = 진화를 한 번 이상 한 전투 ÷ 전체 전투.
- 당겨쓴 턴의 비율 = 턴을 끝낼 때 `memory < 0`이었던 플레이어 턴 ÷ 전체 플레이어 턴.
- 아래 두 줄은 설계 기둥 1("지금 카드를 낼까, 진화에 쓸까")을 재는 지표입니다. 진화가 보람이 있어야 하고(첫 줄), 그렇다고 "무조건 첫 턴 진화"가 정답이면 안 됩니다(둘째 줄). 봇의 진화 방식은 03 7.1에 있습니다.

- 목표에서 벗어나면 `src/data`의 수치만 고칩니다. 규칙을 바꿔야 풀릴 것 같으면 멈추고 사용자에게 묻습니다.
- 지표가 벗어난 까닭이 게임이 아니라 봇의 동작이면, 봇 규칙(03 7.1)을 문서와 함께 고칠 수 있습니다. 무엇을 왜 고쳤는지 `docs/balance/M0.md`에 적습니다.
- 조정한 내용과 측정 결과는 `docs/balance/M0.md`에 남깁니다.

## 12. 2단계 규칙 (T2-1에서 확정)

> 수치는 초기값입니다. T2-7 밸런스에서 `src/data`를 고치고 이 문서의 표도 함께 고칩니다.

### 12.1 막
- `ACT_COUNT = 3`. 막 넘어가기는 7.6 그대로입니다 (1막 보스 → 완전체·메모리 4, 2막 보스 → 궁극체·메모리 5).
- 지도 생성(6절)은 막마다 같고, 그 막의 조우·이벤트 목록만 다릅니다 (12.9, 12.10).
- 이벤트에는 나오는 막 목록 `acts`가 있습니다. 6절 5번의 "그 막의 이벤트 목록"은 `acts`에 그 막이 든 이벤트입니다.

### 12.2 보상 카드가 강화되어 나올 확률
- 전투 보상(7.1: 일반·강적·보스)의 카드 고르기를 만든 뒤, 카드마다 따로 `reward` 난수로 정합니다: `nextInt(100) < UPGRADE_CHANCE[막]`이면 강화된 상태로 보여 줍니다.
- `UPGRADE_CHANCE = { 1: 0, 2: 15, 3: 30 }` (퍼센트). 확률이 0인 막에서는 난수를 쓰지 않습니다 (1막의 결과가 0단계와 같도록).
- 상점, 이벤트의 `offerCards`, 테이머 특성의 카드 고르기에는 쓰지 않습니다.
- 난수 순서: 비트 → (칩) → 카드 고르기 만들기 → 강화 여부를 카드 순서대로.

### 12.6 동료 카드
- 새 카드 종류 `companion`. 원작 인물이 함께 싸우는 카드입니다.
- **내기**: 3.5와 같이 메모리를 내고 냅니다. 내면 버림 더미가 아니라 **동료 자리**(`battle.companions`)에 놓이고, 그 전투가 끝날 때까지 효과가 계속됩니다.
- 동료 자리는 `COMPANION_SLOTS = 2`개입니다. 자리가 차 있으면 동료 카드를 낼 수 없습니다 (3.5의 조건에 추가).
- **효과**: 동료 카드의 면에는 효과 목록 대신 칩과 같은 구조(발동 시점 + 효과, 또는 수치 보정)가 있습니다. 낸 순간에는 발동하지 않고, 다음 발동 시점부터 동작합니다. 수치 보정은 놓인 순간부터 적용됩니다.
- 같은 발동 시점에서는 **칩을 먼저**, 그다음 동료를 자리 순서대로 실행합니다.
- 동료 효과에서도 `target: 'enemy'`는 쓸 수 없습니다 (5절과 같음).
- 전투가 끝나면 동료 자리는 사라집니다 (카드는 런의 덱에 그대로 있음).

### 12.12 밸런스 목표 (2단계, T2-7에서 측정)
- 측정 조건: 테이머 3명 × 3막, 시드 1~1000, 봇 정책별.
- 10절의 지표를 **테이머마다** 잽니다. 승률 목표는 3막 전체를 기준으로 `greedy` 40~60%, `random` 5% 이하로 바꿉니다. 나머지 지표 목표는 10절 그대로이고, 2·3막 보스는 평균 7~12턴입니다.
- 테이머끼리 `greedy` 승률 차이는 10%p 이내.
- 측정 명령: `npm run sim -- --report m2`. 기록은 `docs/balance/M2.md`.
- 10절의 0단계 지표(M0)는 이제 1막만 잽니다 (`--report m0`). 0단계 기록용입니다.
- 한 판 길이: `greedy` 기준 전투 수 평균 12~16번.
